# Local editor — 설계

## 의도

VS Code에서 마크다운, front matter, 이미지 경로를 손으로 다루는 게 번거롭다.
로컬 브라우저에서 블로그 글을 쓰고, 입력하는 대로 실제 블로그 모양을 보면서,
사진과 책 정보를 손쉽게 넣는 개인용 에디터를 만든다. 사용자는 한 명(본인)이고 로컬에서만 쓴다.

시험 버전(`spike/editor` 브랜치, `c7d4bf8`)으로 흐름을 확인했고, 사용자가 "이 흐름으로 제대로 만들자"고 승인했다.
시험 버전 코드는 참고만 하고 새로 만든다.

## 목표

- `bash tools/editor.sh` 한 줄로 켜면 브라우저에서 `http://127.0.0.1:4100`이 열린다.
- 글 흐름: 고르기(Article / Book note) → 쓰기(실시간 미리보기) → 자동 저장(`_drafts/`) → Publish(`_posts/`로 이동).
- 이미지는 붙여넣기나 끌어다 놓기로 넣는다. 파일은 `assets/img/posts/<slug>/`에 저장되고, 링크는 `/`로 시작하는 절대 경로로 들어간다.
- Book note는 책을 고르면 다음 장 번호가 자동으로 제안된다.
- 새 책은 제목으로 검색해 표지, 저자, 출판사를 채우고 `_books/<id>.md`를 만든다. 표지는 `assets/img/books/<id>.jpg`로 내려받는다.
- **slug는 언제든 바꿀 수 있다.** 바꾸면 파일 이름과 이미지 폴더가 함께 옮겨지고, 본문 안 이미지 링크도 새 경로로 고쳐진다. 시험 버전은 첫 저장 뒤 slug를 못 바꿨다. 사용자가 지적한 문제다.
- 디자인은 블로그 디자인 철학을 따른다.
  - 같은 토큰(`base.css`의 색 변수), Pretendard + JetBrains Mono, 다크 모드
  - 미니멀하게, 선을 줄이고, 회색 계층을 쓰고, 포인트 색은 하늘색 하나
- 반응형이다.
  - 넓은 화면: 사이드바 + 입력 + 미리보기 3단
  - 중간 화면: 사이드바를 접고 입력 + 미리보기 2단
  - 좁은 화면: 입력과 미리보기를 탭으로 전환, 사이드바는 서랍(drawer)

## 비목표

- 커밋 / push 버튼. 커밋은 사용자가 직접 한다. 나중에 추가를 검토할 수 있다.
- 여러 사람이 쓰는 것, 인증, 원격 접속. 서버는 127.0.0.1에서만 연다.
- 미리보기에서 Jekyll과 픽셀 단위로 똑같이 그리기. 코드 하이라이트 색은 근사치로 충분하다.
- WYSIWYG(서식 버튼으로 편집). 마크다운 입력이 기본이다.

## 제약

- 런타임은 Node 22를 쓴다. 외부 npm 의존성은 0을 목표로 한다. 서버는 Node 표준 모듈만 쓴다.
- 클라이언트 라이브러리는 CDN에서 고정 버전으로만 불러온다.
  - 마크다운: `marked@12.0.2`
  - 코드 하이라이트: `highlight.js` 고정 버전
- 미리보기는 블로그와 같게 그려야 한다.
  - `assets/css/base.css`, `prose.css`, `syntax.css`를 그대로 불러 쓴다.
  - 블로그는 `kramdown hard_wrap: true`라서 줄 하나 바꿈이 `<br>`이 된다. 미리보기도 `marked`의 `breaks: true`로 맞춘다.
  - 읽는 시간 계산(`ceil(글자 수 / 500)`, 표시 `Nm`)과 날짜 형식(`YYYY-MM-DD`)은 블로그와 같다.
- 파일 쓰기는 `_posts`, `_drafts`, `_books`, `assets/img/posts`, `assets/img/books` 안으로만 허용한다. 경로 이탈은 거부한다.
- front matter 키와 형식은 블로그 규칙을 따른다.
  - Article: `title`, `date`, `image`(선택)
  - Book note: `title`, `date`, `book`, `chapter`
  - 책(`_books`): `title`, `author`, `publisher`, `cover`, `description`, `link`, `tone`(선택)
  - 에디터가 모르는 키는 지우지 않고 보존한다(예: 기존 글의 `description`, `tags`, `categories`).
- `_drafts/`는 Jekyll이 배포하지 않는다. 발행 전 글은 여기에 둔다.
- `tools/`는 `_config.yml`의 `exclude`에 이미 있어서 사이트에 배포되지 않는다.

## 책 추가 (사용자 결정: 도서 검색은 이번 범위에서 제외)

- 책은 직접 입력한다: 제목(필수), 책 id(영문 slug, 필수), 저자, 출판사, 표지 이미지(붙여넣기/끌어다 놓기, 선택).
- 도서 검색 API는 나중에 필요하면 이 입력 칸을 채우는 버튼으로 붙인다.

## (보류) 도서 검색

- `KAKAO_REST_KEY` 환경 변수가 있으면 카카오 책 검색을 쓴다. 한국 책에 가장 좋다.
- 키가 없으면 Google Books를 쓰고, 실패하면 Open Library를 쓴다.
  - 시험 중 Google Books 키 없는 호출은 공용 한도 초과(429)였다.
  - Open Library는 한국 책을 거의 못 찾는다.
- 검색 결과와 상관없이 "제목만으로 추가"를 항상 제공한다. 이때 표지는 블로그의 아이보리 카드가 된다.
- 결과에서 고른 뒤 저자, 출판사, 책 id(영문 slug)를 고칠 수 있다.

## 동작 세부

- **목록:** 초안과 발행된 글을 나눠 보여 준다. 제목으로 거른다.
- **새 글:** slug는 비어 있다가, 사용자가 쓰거나 제목에서 영문 부분으로 제안된다. 한글 제목이면 사용자가 정한다. slug 없이 첫 저장이 되면 `untitled-<시간>`을 쓰고 나중에 바꿀 수 있다.
- **자동 저장:** 입력이 멈추고 0.8초 뒤 저장한다. 상태를 "저장 중 / 저장됨 HH:MM:SS / 오류"로 보여 준다. 저장 실패 시 입력 내용은 브라우저에 남는다.
- **발행된 글 수정:** 열어서 고치면 바로 `_posts/` 파일에 저장된다. 사용자가 이 동작을 알 수 있게 상태 줄에 "발행된 글"이라고 표시한다.
- **Publish:** `_drafts/<slug>.md`를 `_posts/<오늘 날짜>-<slug>.md`로 옮기고, `date`를 지금 시각(Asia/Seoul)으로 넣는다.
- **썸네일(Article):** 본문에 넣은 이미지 중에서 고른다.
- **Book note 장 번호:** 그 책의 기존 최대 장 + 1을 제안하고, 사용자가 고칠 수 있다.
- **이미지 파일 이름:** `<타임스탬프>-<원래 이름 정리본>`이다. 클립보드 이미지는 `image.png`로 한다.

## 리뷰 후 정한 것 (모두 내 판단, 사용자 확인 대상)

- **발행된 글의 slug 변경은 허용하되 확인을 받는다.** 확인 창에 "공개 주소가 `/posts/<옛 slug>/`에서 `/posts/<새 slug>/`로 바뀌고 옛 링크는 끊긴다"고 보여 준다. 리다이렉트는 만들지 않는다. 파일 이름의 날짜 접두사는 원래 발행일을 유지한다. 초안 slug 변경은 확인 없이 바로 한다.
- **front matter는 줄 단위로 고친다.** 에디터가 바꾼 키의 줄만 고치거나 추가하거나 지운다. 나머지 줄(따옴표, 순서, `[Dev, Books]` 같은 목록, 빈 키)은 글자 그대로 둔다. 파일을 열고 아무것도 안 바꾸면 git diff가 생기지 않아야 한다. 본문도 저장 시 그대로 쓴다.
- **발행 취소(글을 다시 초안으로)는 이번 범위에서 뺀다.** 발행은 한 방향이다.
- **에디터 밖에서 파일이 바뀌면 덮어쓰지 않는다.** 열 때 파일의 수정 시각(mtime)을 기억하고, 저장 요청에 함께 보낸다. 디스크의 값과 다르면 서버가 거부한다. 화면은 자동 저장을 멈추고 "다른 곳에서 바뀌었어요"와 [다시 불러오기] [내 내용으로 덮어쓰기]를 보여 준다.
- 장 번호 제안에는 같은 책의 초안도 센다. slug를 바꾸면 썸네일 `image` 경로도 함께 고친다.

## 빌더에게 맡기는 것

- 파일 구성. 단, 서버 로직은 테스트할 수 있게 순수 함수(front matter 파싱·직렬화, 경로 검사, slug 정리, 파일 이동 계획)로 나눈다.
- 화면 세부 배치와 아이콘
- 테스트는 Node 내장 `node:test`로 쓰고, `tools/check-site.sh`에서 함께 돈다.
